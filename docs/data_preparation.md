Подготовка данных — это 80% успеха Continual Pre-Training. Если базовая модель LFM "прочитает" слишком много SEO-спама, битой кодировки или повторяющихся абзацев, ее логические способности деградируют. Она начнет генерировать текст, похожий на дешевые дорвеи.
Промышленный пайплайн очистки данных (Data Wrangling) строится из жестких фильтров. Сегодня стандартом де-факто для этой задачи является библиотека **Data-Trove** от Hugging Face (она работает быстрее и стабильнее обычного datasets).
Вот строгая последовательность просеивания сырого корпуса (например, дампа Common Crawl или CulturaX):
**Языковая фильтрация (Language ID)**
*Отсев случайного мусора*
Даже в архивах, помеченных как &quot;ru&quot;, полно китайских иероглифов и казахского языка. Каждую статью нужно прогнать через легковесный классификатор (стандарт — модель fasttext от Facebook). Оставляйте только те документы, где уверенность модели в том, что это русский язык, превышает 95-98%.**Эвристическая фильтрация (Heuristics)**
*Удаление машинного шума*
Здесь применяются простые правила на регулярных выражениях. Мы удаляем:
Тексты короче 100 слов (они не учат модель логике).
Тексты, где больше 20% слов написаны КАПСОМ (токсичный или рекламный контент).
Документы с зашкаливающим количеством спецсимволов или ссылок (меню сайтов, списки навигации).
Строки с &quot;битой&quot; кодировкой (mojibake), вроде РїСЂРёРІРµС‚.**Глобальная дедупликация (MinHash LSH)**
*Критически важный этап*
Если модель увидит одну и ту же лицензионную плашку или абзац новостей 100 раз, она запомнит ее наизусть (overfitting). Это вызовет скачок функции потерь и убьет способность нейросети к обобщению. Алгоритм MinHash (с LSH) разбивает тексты на N-граммы и находит не только полные копии, но и тексты, совпадающие на 80-90% (например, перепечатки новостей с измененным заголовком). Их нужно безжалостно удалять.**Упаковка контекста (Data Packing)**
*Токенизация и конкатенация*
Видеокарты обучают модель блоками фиксированного размера (например, по 4096 токенов). В реальности документы имеют разную длину: 200 токенов, 1500 токенов. Нельзя просто заполнять пустоты токенами [PAD] — вы сожжете тысячи долларов за вычисление пустоты. Тексты нужно &quot;упаковать&quot; (склеить).
## Как правильно работает Упаковка (Data Packing)
Это финальный шаг перед подачей в GPU. Он гарантирует, что эффективность использования видеопамяти составит 100%.
Вместо того чтобы подавать короткие документы по одному:
[Документ A (500 токенов)] + [PAD] + [PAD]...
Вы склеиваете их через специальный токен окончания текста (<|endoftext|> или EOS) и нарезаете на идеальные куски по размеру контекстного окна модели:
 1. **Единый поток:** Документ A + EOS + Документ B + EOS + Документ C...
 2. **Нарезка (Chunking):**
   * Блок 1 (строго 4096 токенов): Документ A + EOS + Документ B (часть 1)
   * Блок 2 (строго 4096 токенов): Документ B (часть 2) + EOS + Документ C + EOS + ...
## Код для упаковки данных (PyTorch / Transformers)
Если использовать классический datasets, функция группировки (packing) пишется вручную и применяется через .map():
```python
def group_texts(examples, block_size=4096):
    # 1. Склеиваем все токены из батча в один длинный массив
    concatenated_examples = {k: sum(examples[k], []) for k in examples.keys()}
    total_length = len(concatenated_examples[list(examples.keys())[0]])
    
    # 2. Отрезаем "хвост", который не делится нацело на block_size
    if total_length >= block_size:
        total_length = (total_length // block_size) * block_size
        
    # 3. Нарезаем на ровные блоки
    result = {
        k: [t[i : i + block_size] for i in range(0, total_length, block_size)]
        for k, t in concatenated_examples.items()
    }
    
    # Для CPT в каузальных моделях метки (labels) равны входным данным (input_ids)
    result["labels"] = result["input_ids"].copy()
    return result

# Применяем упаковку к датасету
lm_datasets = tokenized_datasets.map(
    group_texts,
    batched=True,
    num_proc=8, # Распараллеливаем на 8 ядер процессора
)

```
В результате lm_datasets будет содержать идеальные тензоры размера [4096], готовые к загрузке в оптимизатор без единого бесполезного паддинга.
